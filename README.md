# ENERGY: лендинг подбора дизельного генератора

Работающий адаптивный лендинг на React 19 / TypeScript / Vinext, серверная отправка в Telegram Bot API, Cloudflare Worker и D1. Материалы взяты с https://energy-generator.com/.

## Состояние проекта

- Подготовлены первый экран, факты о компании, три переключаемых исполнения, три реальных кейса, производство, процесс, FAQ, форма и контакты.
- Форма передаёт выбранное исполнение, контакт, имя, задачу, URL страницы и UTM. Телефон, почта и Telegram поддерживаются как способы связи.
- Telegram-обработчик реализован. Реальная доставка не активирована: рабочие BOT_TOKEN и CHAT_ID не предоставлены.
- При отсутствии реквизитов сервер возвращает 503, форма предлагает позвонить. Успешная отправка показывается только после ответа Telegram `ok: true` с `message_id`.
- Приватный просмотр не является открытой публикацией для рекламного трафика. Доступ к сайту остаётся закрытым до решения владельца.
- Источники, спорные сведения и редакционные решения: [docs/SOURCE_NOTES.md](docs/SOURCE_NOTES.md).

## Локальный запуск

Нужны Node.js 22.13+ и pnpm 11.25.0. Используется зафиксированный pnpm-lock.yaml.

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Откройте URL, который напечатает сервер. Для сборки:

```sh
pnpm build
```

В управляемой среде предпросмотра запуск выполняет `sites-preview`, отдельный сервер поверх него запускать не нужно.

## Подключение Telegram

1. Создайте бота через официальный https://t.me/BotFather или используйте бота компании.
2. Получите токен, добавьте бота в нужную группу или начните личный диалог с ним. У бота должна быть возможность отправлять сообщения в выбранный чат.
3. Определите ID нужного чата. Для форума можно указать TELEGRAM_MESSAGE_THREAD_ID.
4. Внесите значения в серверные переменные окружения. Для локального запуска скопируйте `.dev.vars.example` в `.dev.vars`; пример названий также есть в `.env.example`.

```text
TELEGRAM_BOT_TOKEN
TELEGRAM_CHAT_ID
TELEGRAM_MESSAGE_THREAD_ID   # необязательно
LEAD_HASH_SALT              # необязательно; желательно отдельное случайное значение
```

В размещённой версии задайте секреты через настройки окружения хостинга и примените новым развёртыванием. Реальные значения не должны попадать в Git, клиентский код, URL, логи и переменные с NEXT_PUBLIC_.

Официальная документация метода: https://core.telegram.org/bots/api#sendmessage.

## Хранилище защиты от дублей

Нужен binding Cloudflare D1 `DB`. Встроенное размещение подготавливает базу и применяет миграции из drizzle/ при публикации. Таблица lead_delivery содержит только хеши заявки, контакта/содержимого и IP, статус и временные метки. Сам контакт и текст заявки в базе приложения не сохраняются; они отправляются в Telegram.

Чтобы подготовить локальную базу после сборки, примените каждую ещё не применённую миграцию по порядку:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_white_piledriver.sql
```

Миграции не повторяют создание таблиц при каждом HTTP-запросе. Опубликованная и локальная базы независимы.

Защита: обязательное согласие, проверка Origin, ограничения размера и длины полей, honeypot, минимальное время заполнения, атомарное резервирование отправки в D1 и лимит 4 разных заявок на IP в минуту. Повторы в течение 10 минут не отправляются заново. Истёкшие записи очищаются при последующих запросах. Это базовая защита; при большом объёме спама можно отдельно подключить CAPTCHA/WAF.

При сетевом таймауте Telegram доставка может быть неопределённой: автоматического повтора нет, успех не показывается, резервирование сохраняется на 10 минут. Это снижает риск отправить один контакт несколько раз. Telegram Bot API не предоставляет атомарной транзакции с нашей базой; гарантии exactly-once нет.

## Проверки

```sh
node --test tests/leads.test.mjs
pnpm exec tsc --noEmit
pnpm build
```

Автотесты используют настоящую SQLite со схемой миграции и подменённый HTTP-транспорт. Они проверяют подтверждение Telegram, отказ и сетевую ошибку, отсутствие секретов, неправильные поля, согласие, Origin, лимит размера, конкурентные дубли, ограничение частоты и истечение окна дедупликации. Сообщения при тестах не отправляются.

В браузере проверяются переключение исполнений, перенос в форму, раскрытие кейсов/FAQ, мобильное меню, валидация и честная ошибка без настроенного Telegram. Реальную сквозную доставку необходимо проверить после предоставления токена и ID чата.

## Самостоятельное размещение из GitHub

Проект использует серверный маршрут `/api/leads`: GitHub Pages самостоятельно его не выполняет. Подходящее окружение - Cloudflare Workers с D1. Открытое размещение выполняйте только после согласования запуска.

После сборки создайте свою D1-базу, задайте `CF_WORKER_NAME` и `CLOUDFLARE_D1_DATABASE_ID` в окружении, затем:

```sh
node scripts/prepare-cloudflare.mjs
pnpm exec wrangler d1 migrations apply DB --remote --config dist/server/wrangler.json
pnpm exec wrangler secret put TELEGRAM_BOT_TOKEN --config dist/server/wrangler.json
pnpm exec wrangler secret put TELEGRAM_CHAT_ID --config dist/server/wrangler.json
pnpm exec wrangler deploy --config dist/server/wrangler.json
```

`prepare-cloudflare.mjs` только обновляет конфигурацию в dist и ничего не публикует. После новой сборки его нужно вызвать заново. Настройте Cloudflare-авторизацию штатным способом. Сценарий внешнего размещения подготовлен, но не выполнялся в рамках этой задачи.

Перед открытым запуском замените metadataBase в app/layout.tsx на итоговый домен и согласуйте применимость действующей политики компании к этому домену и маршруту обработки данных. На странице есть ссылка на существующую политику; новый юридический документ не выдумывался.

## Где менять содержание

- `app/page.tsx`: оффер, исполнения, кейсы, FAQ, форма и контакты.
- `app/globals.css`: фирменные цвета, Exo 2 и адаптивные стили.
- `app/layout.tsx`: заголовок, описание и Open Graph.
- `public/assets/`: локальные фотографии, логотипы и шрифты.
- `lib/leads.mjs`: валидация, дедупликация и Telegram.
- `app/api/leads/route.ts`: серверный маршрут и привязка окружения.
- `db/schema.ts`, `drizzle/`: схема защиты от дублей и миграции.

В dataLayer предусмотрены события lead_cta_click, generator_view, lead_sent, lead_error. Счётчик Метрики/GTM не подключён: его идентификатор не предоставлен. Контакты и тексты заявок в события аналитики не передаются.
